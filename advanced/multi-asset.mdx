The `docs/HOWTO.md` operating manual describes a multi-asset variant of the index fund pattern as an additional strategy example. It is documented there as a structural extension of the monthly folder architecture — same `YahooFinance` candle fetcher, same exchange adapter pattern, same BTC trend gate — but covering a single long frame from 2015 onward across four instruments rather than partitioning execution month by month. The folder `content/multi_asset/` is not currently present in the repository; the description below is sourced directly from HOWTO.md and shows what such a folder would contain when created.

## The four instruments

Rather than an equal-weight basket of altcoins, the multi-asset variant covers one instrument per asset class:

| Symbol | Asset class | Yahoo Finance ticker |
|---|---|---|
| `BTCUSD` | Cryptocurrency | `BTC-USD` |
| `GOLD` | Precious metals | `GC=F` — COMEX gold futures |
| `SPX` | Equities | `^GSPC` — S&P 500 index |
| `TLT` | Long-duration bonds | `TLT` — iShares 20+ Year Treasury Bond ETF |

These four instruments are the only differences in the strategy file's constant block — the rest of the architecture (gate computation, weekly hold, `PersistCandleAdapter.useDummy()`, `CC_BACKTEST_STEP_MINUTES`) is identical to the monthly index fund.

## Risk-parity weighting

Rather than dividing the deposit equally by instrument count, the multi-asset strategy sizes each leg so that every instrument contributes the same amount of risk to the portfolio. Weights are derived from the **equal risk contribution (ERC)** principle, using the covariance matrix of 90-day daily returns:

1. The strategy fetches 90 daily bars for all four instruments and computes the sample covariance matrix.
2. ERC weights are solved so that each leg's marginal risk contribution — `w_i × (Σw)_i` — is equal across all four instruments.
3. The **crypto leg** (BTC) is additionally multiplied by the same BTC trend gate used in the monthly index fund: the share of the six windows (20, 25, 30, 35, 40, 45 days) on which Bitcoin closed higher.
4. The fraction released from the crypto leg when the gate is below 1 is **redistributed proportionally** among the remaining three asset classes, preserving their relative ERC weights.

This means the portfolio is always fully invested: when the gate is 0 the entire deposit flows into the three non-crypto instruments at their ERC weights; when the gate is 1 all four instruments are held at their full ERC weights.

## How to run (once the folder exists)

The HOWTO.md run command for this pattern follows the same convention as any monthly folder:

```bash
npm start -- --backtest --entry ./content/multi_asset/main.strategy.ts
```

Because `CC_BACKTEST_STEP_MINUTES` would be set to `24 * 60` — one engine step per daily bar — eleven years of daily candles pass in a matter of minutes.

## Folder structure

When created, the folder follows the exact same layout as every monthly content folder:

| File | Role |
|---|---|
| `main.strategy.ts` | Constants, ERC weight computation, gate logic, allocation, launcher; `setConfig` lives only here |
| `classes/YahooFinance.ts` | Yahoo Finance daily candle fetcher — no API key, no ccxt |
| `modules/backtest.module.ts` | Symbol → Yahoo ticker mapping (`TICKER_OVERRIDES`), exchange schema, single long frame from 2015 |

The `modules/backtest.module.ts` would define `TICKER_OVERRIDES` entries for the non-standard tickers (`GC=F`, `^GSPC`) using the same pattern the monthly modules use for tokens with non-default Yahoo ticker suffixes.

## Data setup

The multi-asset folder uses the same adapter pattern as every other content folder:

- **`getCandlesFilled`** handles `1d` requests: continuous calendar grid, weekend gaps and anomalous bars (zeros, hundredfold wicks) repaired with a flat bar from neighbouring closes.
- **`getCandlesSampled`** handles all intervals shorter than one day by repeating the repaired daily bar across its minutes. There is no intraday price movement in the simulation.
- **`PersistCandleAdapter.useDummy()`** keeps synthesized candles out of MongoDB. The report retains only `opened` and `closed` rows.

<Note>
**Known limitation — sampled daily-bar intraday path.** `getCandlesSampled` copies the daily bar's high, low, and close into every minute of that day. For weekly time-exit positions this does not affect results — the technical stop of −50% is unreachable in one week on spot. For intraday stop strategies this approximation would produce incorrect stop-outs. This trade-off applies equally to every monthly content folder and is documented in `docs/HOWTO.md`.
</Note>
