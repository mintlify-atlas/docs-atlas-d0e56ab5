`generate_months.mjs` is the final step before running the backtest. It reads `scripts/common/universe.json` and produces one self-contained `content/<mon>_<yyyy>/` folder for every month in the file. Each folder is a copy of a single reference month with exactly three targeted substitutions: the coin basket, the Yahoo ticker overrides for those coins, and the calendar frame. The copy-paste model is deliberate — each month folder must be reproducible and independent, so a future refactor of shared code can never silently change a result that has already run.

## Usage

```bash
node scripts/common/generate_months.mjs [--source content/sep_2020]
```

The `--source` flag points to the reference month folder. Default is `content/sep_2020`. The reference folder must contain:
- `main.strategy.ts` with a `// BASKET:BEGIN` … `// BASKET:END` delimited block
- `modules/backtest.module.ts` with a `const TICKER_OVERRIDES: Record<string, string> = { ... };` block and `addFrameSchema`/`startDate`/`endDate`/`frameName` fields
- (optionally) a `classes/` directory

If either required block is absent, the generator throws an error immediately rather than producing silently broken output.

## What Gets Substituted Per Month

The generator makes exactly three substitutions in the copied files:

### 1. Basket block in `main.strategy.ts`

The entire region between `// BASKET:BEGIN` and `// BASKET:END` (inclusive) is replaced with the month's basket from `universe.json`:

```typescript
// BASKET:BEGIN
// September 2020: top-20 Binance USDT spot pairs by August 2020 volume (known before month start),
// listed at least 90 days, no stablecoins, leveraged tokens, or BTC/ETH wrappers.
// Generated by scripts/common/generate_months.mjs from scripts/common/universe.json.
const BASKET = [
  "BTCUSDT",
  "ETHUSDT",
  // ...
];
// BASKET:END
```

Everything outside this block — gate windows, hold time, stop/take levels, deposit amount, position sizing logic — is copied verbatim and is identical across all months.

### 2. Ticker overrides block in `modules/backtest.module.ts`

The `const TICKER_OVERRIDES` object is replaced with only the overrides relevant to the current month's basket. A coin needs an override only when its Yahoo ticker differs from the default `BASE-USD` pattern (e.g. `UNIUSDT` maps to `UNI7083-USD`, not `UNI-USD`). `PAXGUSDT` overrides are always included because the gold leg appears in every month.

```typescript
const TICKER_OVERRIDES: Record<string, string> = {
  UNIUSDT: "UNI7083-USD",
  RNDRUSDT: "RENDER-USD",
};
```

If any basket coin is absent from `yahoo_tickers.json` (unchecked) or mapped to `null` (no Yahoo data), the generator throws rather than producing a broken month. This enforces the resolve → verify → build convergence loop.

### 3. Frame fields in `modules/backtest.module.ts`

The `addFrameSchema` call has four fields updated to target the correct calendar month:

| Field | Example value |
|-------|---------------|
| `frameName` | `"sep_2020_frame"` |
| `startDate` | `new Date("2020-09-01T00:00:00Z")` |
| `endDate` | `new Date("2020-09-30T23:59:59Z")` |
| `note` | `"September 2020"` |

The end date uses the actual last calendar day of the target month, computed correctly for months of different lengths.

## What Is Never Touched

All strategy logic in `main.strategy.ts` outside the `BASKET:BEGIN`/`BASKET:END` block is copied as-is and is never modified by the generator:

- Gate windows (20, 25, 30, 35, 40, 45 days)
- Hold time (one week minus one minute)
- Stop and take-profit levels (−50% / +500%)
- Deposit amount and allocation arithmetic
- The `setConfig` call and all engine settings
- The gate caching logic (`Cache.fn`)

This means every month runs the exact same strategy logic, differing only in which coins are in the basket, which Yahoo tickers map to those coins, and which calendar interval the frame covers.

## The `classes/` Directory

If the reference month contains a `classes/` directory (e.g. `classes/YahooFinance.ts`), it is copied file-by-file into every generated month folder. These files provide the candle source and utilities used by the strategy and exchange adapter. They are not modified.

## Runner Scripts Rewritten

After stamping all month folders, the generator rewrites two runner scripts that list every generated month:

| Script | Platform |
|--------|----------|
| `scripts/linux/generate_strategy.sh` | Linux / macOS |
| `scripts/win/generate_strategy.bat` | Windows |

Each script runs one engine process per month in chronological order. The scripts are regenerated from scratch on every call to `generate_months.mjs`, so they always reflect exactly the set of folders currently on disk. A month that exits with a non-zero status (the engine terminates each month via `kill()`, producing exit code 137) does not abort the runner — this is the normal, expected exit path.

## Editing the Strategy

To change the strategy logic across all months, edit **only** the reference month file `content/sep_2020/main.strategy.ts` (or the folder passed to `--source`), then re-run the generator:

```bash
node scripts/common/generate_months.mjs --source content/sep_2020
```

Never hand-edit individual month files. The generator will overwrite them on the next run, and any manual changes will be lost.

<Tip>
**Extending the backtest range.** To add months beyond the current `--to` date, run `build_universe.mjs` with the updated range first, then work through the resolve/verify convergence loop for any newly added coins, then call `generate_months.mjs` again:

```bash
node scripts/common/build_universe.mjs --top 20 --from 2020-09 --to 2027-09
node scripts/common/resolve_yahoo_tickers.mjs
# repeat until no unchecked coins
node scripts/common/verify_yahoo_tickers.mjs
# repeat loop if any coins are rejected
node scripts/common/generate_months.mjs --source content/sep_2020
```

The generator is safe to re-run: it overwrites existing folders cleanly and regenerates the runner scripts.
</Tip>
